DLC e payload

No CAN clássico, cada Data Frame transporta de zero a oito bytes de payload. O DLC informa quantos bytes válidos seguem no campo de dados; o significado desses bytes vem do protocolo da ECU.

0–8 bytes · leitura de mensagens · exemplos

DLC não é o payload

DLC (Data Length Code)

É o código de 4 bits no campo de controle que indica o comprimento do campo de dados de um Data Frame CAN clássico. Para payloads clássicos de 0 a 8 bytes, o valor do DLC corresponde diretamente à quantidade de bytes.

Payload

São os bytes de dados efetivamente transportados no frame. O payload pode conter um valor, vários sinais empacotados, contadores, flags ou comandos definidos pela aplicação.

O DLC tem quatro bits porque o campo representa um código. No CAN clássico, o payload máximo continua sendo 8 bytes; não se pode concluir que um frame clássico transporta até 15 bytes só porque o campo DLC tem 4 bits.

DLC 0 é permitido: um Data Frame pode conter zero bytes de dados. Nesse caso, ID e periodicidade ainda podem ter significado para a rede, mas não há bytes de payload.

Velocidade

Os bytes 0–1 são little-endian: 0x0369 = 873. A escala é 0,1 km/h por unidade, então a velocidade é 87,3 km/h.

Temperatura e acelerador

0x69 = 105; subtraindo o offset 40, a temperatura é 65 °C. 0x32 = 50 decimal, logo o acelerador está em 50%.

Os bytes esmaecidos não são transmitidos. O DLC 4 significa que o payload termina após o Byte 3. Não interprete bytes 4–7 como zeros nem como parte da mensagem.

Como ler e projetar o campo de dados

1

Leia o ID e o DLC. O ID seleciona a definição da mensagem; o DLC diz quantos bytes de payload estão presentes no Data Frame.

2

Separe os bytes por posição. Byte 0 é o primeiro byte do payload. A ordem de bytes de um sinal multibyte deve vir do protocolo da aplicação, não do número do ID.

3

Aplique escala, offset e unidade. Um valor bruto pode precisar de multiplicador e deslocamento para virar rpm, km/h, °C ou outra unidade.

4

Não leia além do DLC. Só os primeiros DLC bytes existem no payload daquele frame. Bytes usados para preencher estruturas de memória não são necessariamente bytes transmitidos.

Remote Frame não leva payload

No CAN clássico, um Remote Frame pode ter DLC indicando o comprimento solicitado, mas não contém bytes de dados. Não confunda esse caso com um Data Frame cujo DLC informa bytes presentes.

CAN FD tem regras diferentes

CAN FD pode carregar até 64 bytes e usa códigos DLC de 0 a 15 com mapeamento próprio para comprimentos maiores que 8. A tabela desta página vale somente para CAN clássico.

Revisão rápida

O que o DLC informa?

O comprimento do payload no Data Frame clássico: neste contexto, de 0 a 8 bytes.

O DLC explica os sinais?

Não. A especificação da mensagem define campos, ordem dos bytes, escala, offset, unidade e significado.

O que significa A0 0F?

Depende do contrato da mensagem. Na tabela fictícia, são 4000 unidades little-endian, escaladas para 1000 rpm.

Este material usa CAN clássico e payloads de até 8 bytes. Os IDs e a tabela ECU-Motor são fictícios e servem apenas para demonstrar como documentar um protocolo.
