Prática com CAN virtual

Use vcan0 para enviar e observar frames CAN sem hardware físico. Neste roteiro você compara payloads de 1, 4 e 8 bytes, filtra mensagens pelo identificador e executa um transmissor periódico que grava a captura.

vcan0 · candump · cansend

O que é VCAN e por que foi desenvolvido?

VCAN (Virtual CAN) é o dispositivo CAN virtual do Linux, integrado à interface SocketCAN. Ele cria interfaces, como vcan0, para que programas e ferramentas troquem frames CAN pelo kernel sem precisar de uma placa CAN, transceptor ou cabeamento físico.

Foi desenvolvido para facilitar a criação, o teste e a depuração de software CAN em um ambiente controlado e acessível. Assim, desenvolvedores podem exercitar aplicações, observar mensagens e automatizar testes mesmo sem o veículo ou o hardware final conectado.

O VCAN reproduz o caminho de comunicação usado pelas aplicações SocketCAN, mas não reproduz as propriedades elétricas nem a temporização de um barramento real. Portanto, é adequado para testes de software e integração, não para validar transceptores, bitrate físico, ruído ou sinalização elétrica.

Preparar o ambiente

O laboratório requer Linux com suporte a vcan e os utilitários candump e cansend, disponíveis no pacote can-utils. Crie e ative uma interface virtual:

sudo apt install can-utils

Depois, carregue o módulo e prepare a interface:

sudo modprobe vcan
sudo ip link add dev vcan0 type vcan
sudo ip link set dev vcan0 up

Se vcan0 já existir, não repita o comando ip link add; confirme o estado com ip link show dev vcan0. A criação e a ativação da interface exigem permissões administrativas.

Sem hardware físico: vcan permite exercitar sockets CAN e ferramentas no mesmo computador, mas não simula níveis elétricos, bitrate real, ruído, transceptores ou temporização física de um veículo.

1. Observar mensagens com candump

Abra um terminal para observar todos os frames que passam pela interface:

candump vcan0

Deixe o comando em execução. Em um segundo terminal, envie os frames da próxima seção. A captura mostra o ID, o DLC entre colchetes e os bytes hexadecimais do payload.

vcan0  123   [1]  AA
vcan0  124   [4]  11 22 33 44
vcan0  125   [8]  00 11 22 33 44 55 66 77

Saída ilustrativa esperada para os três comandos seguintes; horários, espaçamento e formatação podem variar conforme a versão do candump.

2. Enviar IDs e payloads diferentes com cansend

O formato básico para um Data Frame é cansend interface ID#payload. O ID e os bytes são escritos em hexadecimal; cada par de dígitos do payload representa um byte.

cansend vcan0 123#AA
cansend vcan0 124#11223344
cansend vcan0 125#0011223344556677

Os três IDs são padrão de 11 bits. Os payloads têm, respectivamente, 1, 4 e 8 bytes. Na notação do cansend não se escreve 0x antes do ID; # separa ID e dados.

3. Comparar frames de 1, 4 e 8 bytes

IDDLCPayload enviadoBytes no payloadO que observar
0x1231AA1Um único byte de dados.
0x124411 22 33 444Quatro bytes; a ordem aparece igual à sequência enviada.
0x125800 11 22 33 44 55 66 778Payload máximo de um Data Frame CAN clássico.
O que muda: crescem o DLC e o campo de dados. O identificador não define o comprimento nem o significado dos bytes. Na rede física, o número total de bits do frame também depende de campos de controle e bit stuffing; vcan não mede duração de transmissão no fio.

4. Filtrar por identificador

Somente o ID 0x123

candump vcan0,123:7FF

O filtro compara os 11 bits do identificador padrão. Enquanto ele estiver rodando, envie os três frames: somente as mensagens de 0x123 devem aparecer.

Somente o ID 0x124

candump vcan0,124:7FF

Troque o valor antes dos dois-pontos para selecionar outro ID. A máscara 7FF marca todos os 11 bits do ID padrão como relevantes no filtro.

Execute o filtro em um terminal separado; pare a captura com Ctrl+C. Os comandos acima são para IDs padrão usados neste laboratório.

5. Enviar periodicamente e registrar a captura

O programa deste tópico está incluído como código nesta página. Para executá-lo, expanda “Ver o código completo do script”, copie todo o conteúdo e salve em um arquivo chamado vcan_demo.sh. O código inicia candump, transmite os frames com cansend e registra a captura automaticamente; não é necessário iniciar um segundo candump em outro terminal.

Ver o código completo do script para copiar 
#!/usr/bin/env bash
set -Eeuo pipefail

interface=${1:-vcan0}
cycles=${2:-10}
log_file=${3:-"vcan-demo-$(date +%Y%m%d-%H%M%S).log"}
capture_pid=

if [[ ! $cycles =~ ^[1-9][0-9]*$ ]]; then
    printf 'Erro: ciclos deve ser um inteiro positivo.\n' >&2
    printf 'Uso: %s [interface] [ciclos] [arquivo-de-log]\n' "$0" >&2
    exit 2
fi

for command_name in ip candump cansend; do
    if ! command -v "$command_name" >/dev/null 2>&1; then
        printf 'Erro: comando obrigatório não encontrado: %s\n' "$command_name" >&2
        exit 127
    fi
done

if ! ip link show dev "$interface" >/dev/null 2>&1; then
    printf 'Erro: interface CAN "%s" não existe ou não está acessível.\n' "$interface" >&2
    printf 'Ative uma interface vcan antes de executar o script.\n' >&2
    exit 1
fi

if [[ -e $log_file ]]; then
    printf 'Erro: o arquivo de log já existe; escolha outro caminho: %s\n' "$log_file" >&2
    exit 1
fi

mkdir -p -- "$(dirname -- "$log_file")"
: > "$log_file"

candump -L -t a "$interface" > "$log_file" 2>&1 &
capture_pid=$!

stop_capture()
{
    if [[ -z $capture_pid ]]; then
        return 0
    fi

    local status=0
    if kill -0 "$capture_pid" 2>/dev/null; then
        kill -INT "$capture_pid"
    fi
    wait "$capture_pid" || status=$?
    capture_pid=

    if [[ $status -ne 0 && $status -ne 130 ]]; then
        printf 'Erro: candump encerrou com status %s; consulte %s\n' "$status" "$log_file" >&2
        return "$status"
    fi
}

trap stop_capture EXIT
trap 'exit 130' INT
trap 'exit 143' TERM

sleep 0.2
if ! kill -0 "$capture_pid" 2>/dev/null; then
    status=0
    wait "$capture_pid" || status=$?
    capture_pid=
    printf 'Erro: candump não iniciou (status %s); consulte %s\n' "$status" "$log_file" >&2
    exit 1
fi

printf 'Capturando em %s; interface=%s; ciclos=%s\n' "$log_file" "$interface" "$cycles"
for ((cycle = 1; cycle <= cycles; cycle++)); do
    printf '[%s/%s] enviando IDs 123 (1 byte), 124 (4 bytes), 125 (8 bytes)\n' \
        "$cycle" "$cycles"
    cansend "$interface" 123#AA
    cansend "$interface" 124#11223344
    cansend "$interface" 125#0011223344556677

    if ((cycle < cycles)); then
        sleep 1
    fi
done

printf 'Envio concluído. Frames capturados em: %s\n' "$log_file"
1

2

Copie: expanda o bloco de código abaixo, copie o script inteiro e salve como vcan_demo.sh. A partir do terminal, vá até a pasta onde salvou o arquivo.

3

Execute: rode o script com Bash. Ele inicia a captura antes de transmitir para reduzir o risco de perder os primeiros frames.

Com os valores padrão, execute:

bash vcan_demo.sh

Para passar os argumentos explicitamente, use:

bash vcan_demo.sh vcan0 5 /tmp/vcan-demo-5-ciclos.log

O caminho de log escolhido não pode existir ainda: por segurança, o script não sobrescreve arquivos.

Com 10 ciclos, o script envia 30 frames (10 de cada ID) em aproximadamente 9 segundos, além do tempo de inicialização. Os três frames de cada ciclo são enviados em sequência; a pausa de 1 segundo ocorre entre os ciclos.

Durante a execução, o terminal informa o progresso e o caminho do log. Ao terminar, copie esse caminho para consultar a captura:

Capturando em /tmp/vcan-demo-5-ciclos.log; interface=vcan0; ciclos=5
[1/5] enviando IDs 123 (1 byte), 124 (4 bytes), 125 (8 bytes)
...
Envio concluído. Frames capturados em: /tmp/vcan-demo-5-ciclos.log

A saída é ilustrativa. O caminho e os timestamps dependem dos argumentos e do momento em que o script for executado.

O arquivo contém as mensagens capturadas pelo candump em formato de log, com timestamp:

(timestamp) vcan0 123#AA
(timestamp) vcan0 124#11223344
(timestamp) vcan0 125#0011223344556677

Formato ilustrativo de um trecho do log em modo -L. O arquivo real inclui timestamps gerados no momento da captura.

Para consultar os últimos frames do exemplo com caminho personalizado, execute:

tail -n 12 /tmp/vcan-demo-5-ciclos.log

Se interromper com Ctrl+C, o script encerra candump e mantém no arquivo as mensagens capturadas até aquele momento. O log contém os frames; as mensagens de progresso aparecem no terminal.

Revisão e diagnóstico

Nada aparece?

Confirme que vcan0 existe e está ativa, e que candump e cansend usam o mesmo nome de interface.

O DLC está diferente?

Conte os pares hexadecimais do payload: 2 dígitos = 1 byte. O DLC deve ser 1, 4 e 8 nos exemplos.

O filtro mostra outros IDs?

Confira o ID e a máscara. 123:7FF filtra os 11 bits do ID padrão 0x123.

Segurança: execute este transmissor apenas em uma interface virtual de teste. Em um barramento físico, frames de teste podem interferir nos módulos conectados.

Este roteiro usa CAN clássico com até 8 bytes por frame. Uma interface vcan valida o fluxo de dados via SocketCAN, não o comportamento elétrico nem os tempos de uma rede CAN física.
