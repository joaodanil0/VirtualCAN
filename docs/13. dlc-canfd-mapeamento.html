CAN FD · Comprimento do payload

DLC e payload acima de 8 bytes

No CAN FD, o DLC continua sendo um código de 4 bits, mas não representa diretamente o número de bytes para todos os valores. A partir do DLC 9, cada código mapeia para um comprimento maior específico, até o máximo de 64 bytes.

16 códigos · 0 a 64 bytes · mapeamento não linear

DLC é código; comprimento é quantidade de bytes

O campo DLC (Data Length Code) tem quatro bits e pode representar 16 códigos, de 0 a 15. No CAN clássico, o payload é limitado a 8 bytes. No CAN FD, os códigos 0–8 continuam correspondendo diretamente a 0–8 bytes; os códigos 9–15 selecionam comprimentos maiores tabelados.

Não faça conversão direta depois de 8: DLC 9 significa 12 bytes, não 9; DLC 15 significa 64 bytes, não 15.

Os comprimentos possíveis no payload FD são 0–8, 12, 16, 20, 24, 32, 48 e 64 bytes. Os comprimentos de 9, 10, 11, 13–15, 17–19 e 25–31 bytes não têm códigos DLC próprios no barramento CAN FD.

Como interpretar os códigos maiores que 8

1

Leia o código DLC. Ele é um valor entre 0 e 15 indicado pelo campo de quatro bits.

2

Consulte o mapeamento FD. Por exemplo, código 9 corresponde a 12 bytes; código 13 corresponde a 32 bytes.

3

Leia essa quantidade de bytes do payload. DLC 9 significa que há 12 bytes válidos no frame. Os bytes restantes de um buffer de 64 posições não fazem parte daquele payload.

4

Interprete os bytes conforme a aplicação. O DLC define apenas o comprimento, não o significado, a escala ou a ordem dos sinais.

DLC 9

O nibble enviado é 1001 (decimal 9), mas o frame transporta 12 bytes.

DLC 15

O nibble enviado é 1111 (decimal 15), mas o frame transporta 64 bytes.

O buffer de software pode ter capacidade para 64 bytes; o comprimento deste frame específico continua sendo 12 bytes.

DLC no barramento e comprimento nas APIs

O campo transmitido no frame é o código DLC. Muitas APIs de software, incluindo a estrutura CanFdFrame deste projeto, expõem o comprimento em bytes por meio de len, não o nibble DLC bruto.

const uint8_t payload[] = {
    0x10, 0x20, 0x30, 0x40, 0x50, 0x60,
    0x70, 0x80, 0x90, 0xA0, 0xB0, 0xC0
};

// 12 bytes de payload; no fio, corresponde ao DLC 9.
bus.sendFrame(0x123, payload, 12);

O controlador ou a camada SocketCAN traduz o comprimento em bytes para a codificação DLC do frame CAN FD. A aplicação deve seguir os comprimentos suportados pela interface e pelo protocolo.

O que não confundir: FDF identifica o formato CAN FD; BRS controla a troca de bitrate; DLC codifica o comprimento. BRS não altera o mapeamento do DLC.

CAN clássico, CAN FD e ferramentas de captura

CAN clássico

Payload máximo de 8 bytes. Os códigos 9–15 não permitem transportar payloads maiores que 8 bytes em um frame clássico.

CAN FD

Payload máximo de 64 bytes, com os códigos DLC 9–15 mapeados para comprimentos específicos.

Logs e APIs

Uma ferramenta pode exibir o comprimento em bytes, enquanto a especificação define o código DLC no fio. Confira a convenção de cada saída.

Este projeto armazena o comprimento em bytes no campo CanFdFrame.len. Para uma explicação completa dos campos FDF, BRS e ESI, consulte Estrutura do frame CAN FD.
