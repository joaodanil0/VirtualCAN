Arbitragem CAN

Quando várias ECUs tentam transmitir ao mesmo tempo, o CAN resolve qual continua usando o barramento sem corromper o frame vencedor. A prioridade é decidida bit a bit pela combinação de identificadores e dos estados dominante e recessivo.

Prioridade · lógica bit a bit · 0x100 vs 0x200

Por que existe arbitragem?

O barramento CAN é compartilhado: qualquer nó pode iniciar uma transmissão quando o meio está livre. Se duas ou mais ECUs começam juntas, todas transmitem e monitoram o barramento simultaneamente. Durante o campo de arbitragem, cada nó compara o bit que enviou com o bit que lê do barramento.

Exemplo: a ECU de freios tem um frame pronto com ID 0x100 e a ECU de motor tem outro com ID 0x200. Se ambas estiverem prontas quando o barramento fica livre, as duas começam o SOF na mesma oportunidade e passam a disputar o barramento. “Ao mesmo tempo” quer dizer que tentam iniciar na mesma janela de barramento livre — não que os dados tenham sido calculados no mesmo instante pelo relógio interno das ECUs. Se a segunda mensagem ficar pronta depois que um frame já começou, ela espera; não pode entrar no meio da transmissão.

A arbitragem não funciona como um sorteio nem como uma mensagem de controle separada. O próprio padrão de bits dos campos de arbitragem determina qual frame tem prioridade. O vencedor continua a transmissão; os outros param de transmitir e passam a receber o frame vencedor.

Resultado: vários nós podem competir, mas apenas o frame vencedor prossegue. Como os nós perdedores percebem a perda antes de continuar com campos diferentes, não há colisão destrutiva nem corrupção causada pela arbitragem.

Dominante e recessivo

O CAN combina os bits de vários transmissores de modo que o dominante prevalece. A lógica vista no barramento se comporta como um AND de bits: zero domina um.

Dominante = 0

O nó dirige o par CAN para o estado dominante. Em CAN de alta velocidade, CAN_H e CAN_L ficam com uma diferença de tensão perceptível (valores típicos aproximados de 3,5 V e 1,5 V).

Recessivo = 1

O nó não força o estado dominante; se todos enviarem recessivo, o barramento permanece recessivo (valores típicos próximos de 2,5 V em cada fio de um transceptor de alta velocidade).

Como o identificador define a prioridade

Para identificadores do mesmo formato, o campo de ID é enviado do bit mais significativo para o menos significativo. Se dois transmissores enviarem bits diferentes na mesma posição, o valor dominante 0 mantém o barramento dominante. O transmissor que enviou 1, mas leu 0, percebe que perdeu a arbitragem.

Por isso, para IDs CAN padrão de 11 bits, o menor valor numérico tem maior prioridade. Essa regra considera apenas os bits do identificador quando se comparam IDs do mesmo formato; em casos como formato padrão versus estendido, campos de controle da arbitragem também participam.

ID 0x100

0x100 = 256 decimal. Escrito com 11 bits: 00100000000.

ID 0x200

0x200 = 512 decimal. Escrito com 11 bits: 01000000000.

ID10 é enviado primeiro. Os dois IDs começam com 0 em ID10, então continuam empatados. A primeira diferença é ID9: 0x100 envia 0; 0x200 envia 1. O barramento fica dominante (0), e a ECU que enviava 0x200 detecta a perda.

Passo a passo: 0x100 disputa com 0x200

1

O barramento está livre. Depois do intervalo recessivo, as duas ECUs iniciam um frame padrão ao mesmo tempo. Ambas enviam o SOF dominante.

2

Comparam ID10. O primeiro bit do ID é 0 nos dois casos; o barramento permanece dominante, então nenhum nó perde ainda.

3

Comparam ID9. A ECU de 0x100 envia 0; a de 0x200 envia 1. Como 0 é dominante, o estado observado é 0.

4

0x200 detecta a perda. Essa ECU transmitiu recessivo (1), mas leu dominante (0). Ela interrompe a própria transmissão sem sinalizar erro e passa a receber o frame que venceu.

5

0x100 termina o frame. O restante do ID, os campos de controle, os dados e os campos finais seguem sem interrupção. A ECU de 0x200 pode tentar novamente quando o barramento estiver livre.

A perda de arbitragem não é um erro de bit. É um resultado normal e previsto. Diferentemente de uma falha de transmissão, ela não gera um frame de erro nem exige que o vencedor reinicie.

Condições e consequências práticas

Precisa haver disputa

A arbitragem decide entre nós que iniciam juntos. Uma ECU que encontra o barramento ocupado não interrompe o frame em andamento; aguarda uma oportunidade de transmissão.

O ID também é prioridade

IDs baixos podem ganhar repetidamente de IDs altos se houver tráfego contínuo de alta prioridade. Ao projetar uma rede, considere deadlines e evite starvation das mensagens de menor prioridade.

Mesmo ID exige coordenação

Se dois nós transmitirem simultaneamente o mesmo ID e os mesmos campos de arbitragem, a disputa pode continuar além do ID. IDs usados por produtores diferentes devem ser coordenados; dados divergentes podem provocar erro de bit.

O exemplo vale para este caso

A comparação 0x100 versus 0x200 assume dois frames CAN clássicos com identificadores padrão de 11 bits e mesma condição nos demais campos de arbitragem até o bit que decide o resultado. Para uma visão detalhada da notação hexadecimal e dos formatos de 11 e 29 bits, consulte Identificadores CAN.
