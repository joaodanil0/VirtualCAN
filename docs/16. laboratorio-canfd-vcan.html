Experimentar frames FD com vcan

Configure uma interface virtual SocketCAN para CAN FD, observe os frames com candump e envie mensagens de 8, 12 e 64 bytes com cansend. O exercício valida o caminho de software sem precisar de um barramento físico.

vcanfd0 · candump · cansend

1. Instalar ferramentas e preparar a interface

Em Linux, instale can-utils para obter candump e cansend:

sudo apt install can-utils

Carregue o módulo vcan e crie uma interface com MTU de 72 bytes, o tamanho da estrutura SocketCAN de um frame FD completo:

sudo modprobe vcan
sudo ip link add dev vcanfd0 type vcan
sudo ip link set dev vcanfd0 mtu 72
sudo ip link set dev vcanfd0 up

Confirme o estado e o MTU:

ip -details link show dev vcanfd0

Se vcanfd0 já existir, não repita ip link add; confirme que está ativa e com MTU 72. Para removê-la ao terminar (somente se você a criou para este teste): sudo ip link delete dev vcanfd0.

MTU 72 não é payload de 72 bytes. É o tamanho da estrutura CAN FD completa usada pelo SocketCAN; o payload máximo transportado no frame é 64 bytes.

2. Observar frames com candump

Em um terminal, inicie a captura antes de enviar:

candump vcanfd0

Deixe esse processo em execução. Os frames que chegam à interface serão exibidos com ID, comprimento de dados e bytes recebidos.

3. Entender a sintaxe de cansend para FD

Para um frame clássico, cansend usa um único #. Para CAN FD, usa ##, seguido por um dígito hexadecimal de flags e depois os dados:

can_id##flagsdata
ParteSignificado neste roteiro
can_idIdentificador em hexadecimal, sem prefixo 0x.
##Indica que o frame usa o formato CAN FD.
flagsUm dígito hexadecimal. 0 não habilita BRS; 1 ativa o flag BRS.
dataPares de dígitos hexadecimais; cada par representa um byte. O DLC é derivado do comprimento do payload conforme o mapeamento CAN FD.
Importante: o dígito de flags vem imediatamente antes dos dados. Por exemplo, em 123##0AABB..., o 0 é o flag e AA inicia o payload.

4. Enviar frames clássicos e FD

Abra outro terminal e envie as mensagens abaixo:

# CAN clássico: 8 bytes
cansend vcanfd0 123#0011223344556677

# CAN FD: DLC 9 corresponde a 12 bytes, sem BRS
cansend vcanfd0 123##0AABBCCDDEEFF001122334455

# CAN FD: DLC 15 corresponde a 64 bytes, com flag BRS
cansend vcanfd0 321##1000102030405060708090A0B0C0D0E0F101112131415161718191A1B1C1D1E1F202122232425262728292A2B2C2D2E2F303132333435363738393A3B3C3D3E3F
ComandoFormatoDLCPayloadFlag
123#...Clássico88 bytesNão se aplica
123##0...CAN FD912 bytesBRS desabilitado
321##1...CAN FD1564 bytesBRS habilitado

O payload de 64 bytes percorre os valores de 00 a 3F. Os comprimentos FD válidos são 0–8, 12, 16, 20, 24, 32, 48 e 64 bytes; 9 bytes, por exemplo, não têm código DLC próprio.

5. Comparar o resultado no terminal

Em candump, compare ID e comprimento:

vcanfd0  123  [8]   00 11 22 33 44 55 66 77
vcanfd0  123  [12]  AA BB CC DD EE FF 00 11 22 33 44 55
vcanfd0  321  [64]  00 01 02 03 ... 3C 3D 3E 3F

Saída esquemática; espaços, indicação de flags e notação variam por versão e opções do candump.

O ID 0x123 aparece duas vezes: um frame clássico de 8 bytes e um frame FD de 12 bytes. O prefixo ## seleciona FD, e o flag 1 no frame de ID 0x321 solicita BRS.

O que vcan não demonstra: a interface virtual transporta os flags e os bytes pela pilha de software, mas não troca de bitrate fisicamente. Assim, o frame com BRS pode ser observado, mas a temporização de 2 Mbit/s exige hardware CAN FD.

6. Filtrar e registrar a captura

Filtrar pelo ID 0x123

candump vcanfd0,123:7FF

O filtro mantém os frames com ID padrão 0x123, incluindo o clássico de 8 bytes e o FD de 12 bytes.

Gravar em arquivo

candump -L -t a vcanfd0 > canfd-vcan.log

Envie os frames em outro terminal e finalize a captura com Ctrl+C. O arquivo registra as mensagens observadas com timestamp.

Diagnóstico rápido

MTU incorreto

Para frames FD, confirme que vcanfd0 tem MTU 72 e está ativa.

Comprimento sem DLC

Use um tamanho válido: para mais de 8 bytes, escolha 12, 16, 20, 24, 32, 48 ou 64.

Formato de comando

Use # para clássico e ##flags para FD. O nibble de flags é obrigatório após ##.

Teste físico é diferente: para validar BRS, bit timing, transceptores e integridade elétrica, use uma rede CAN FD de hardware compatível e assegure que todos os nós suportam os frames FD transmitidos.

Para testar os exemplos do projeto, consulte também CAN clássico vs CAN FD e a configuração de interfaces vcan.
